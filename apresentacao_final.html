4. Pipeline Do dado bruto ao tensor de treino

Pipeline `tf.data` com controle de determinismo e recursos

A carga dos dados foi implementada em `src/plant_village/data.py`, com validação de regras e buffers limitados para evitar uso excessivo de CPU/RAM.

A

`tfds.load("plant_village", as_supervised=True, shuffle_files=False)`.

B

Shuffle determinístico antes do split 70/15/15.

C

`tf.image.resize`, cast para `float32`, batch e prefetch controlado.

D

Data augmentation fica dentro do modelo e roda apenas em treino.

`ExperimentConfig` valida batch, épocas, learning rate, ratios e buffers.
5. Modelo escolhido MobileNetV2 com transfer learning

Arquitetura do modelo final

  • Entrada `224x224x3`.
  • Aumento de dados: flip horizontal, rotação 0.08 e zoom 0.10.
  • Pre-processamento MobileNetV2: escala para intervalo `[-1, 1]`.
  • Backbone MobileNetV2 `include_top=False`, pesos ImageNet.
  • Cabeçalho: GlobalAveragePooling2D, Dropout 0.3 e Dense softmax.
Componente Função
Data augmentation Regularização visual no treino
MobileNetV2 Backbone convolucional pré-treinado
GlobalAveragePooling2D Condensar mapas de características
Dropout Regularização do classificador
Dense softmax Gerar probabilidade para 38 classes
O backbone ficou congelado no treino principal; o projeto suporta fine tuning por flag.
6. Treinamento Experimento final

Treinamento controlado em Docker com GPU NVIDIA

20 épocas
8 batch size
2 CPUs no Docker
8 GB limite de RAM

Hiperparâmetros e callbacks

  • Otimizador Adam com learning rate inicial `1e-3`.
  • Loss `sparse_categorical_crossentropy`.
  • Checkpoint pelo melhor `val_accuracy`.
  • EarlyStopping monitorando `val_loss`.
  • ReduceLROnPlateau para reduzir learning rate.
GPU reduziu a primeira época de aproximadamente 944s para 111s.
TensorFlow criou a GPU com memory growth; o container ficou limitado a 2 CPUs e 8 GB.
7. Curva de treino Aprendizado e validação

Comportamento do treino

A validação melhorou rapidamente no início e depois passou por ajustes menores. O learning rate foi reduzido automaticamente quando `val_loss` parou de melhorar.

Melhor `val_accuracy`: 0.9596. Menor `val_loss`: 0.1319.

12. Teste com erros Casos úteis para análise

Os erros mostram onde o modelo ainda confunde classes

A avaliação também salva exemplos em que a predição foi diferente da classe real. Isso é importante porque mostra limitações do modelo, não apenas o resultado médio.

  • `Soybean___healthy` → `Apple___healthy`, confiança 99,99%.
  • `Tomato___Late_blight` → `Tomato___healthy`, confiança 99,98%.
  • `Potato___Late_blight` → `Tomato___Late_blight`, confiança 99,98%.
Erros com alta confiança indicam que precisamos olhar para classes parecidas, qualidade visual das imagens e generalização fora da base.

13. Conclusões O que aprendemos

Conclusões técnicas

Modelo

MobileNetV2 com transfer learning atingiu 95,40% de acurácia no teste.

Engenharia

O projeto ficou reprodutível: CLI, testes, metadados, modelo e artefatos versionados.

Próximos passos técnicos: fine tuning progressivo, validação fora do PlantVillage, comparação com EfficientNet, análise por classe e teste com imagens reais capturadas em condições menos controladas.
